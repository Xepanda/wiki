# Paperclip 首次使用与 CLI 模型连接

Paperclip 是任务编排与运行记录的网页控制台：为项目创建任务、分配 Agent，配置执行方式，再查看运行结果。Herdr 管理人工交互的持久终端，Collie 把这些终端带到浏览器。使用 Collie 不需要先配置 Paperclip，Paperclip 原生 Run 也不会自动出现在 Herdr 中。

截至 **2026-10-10**，Paperclip 主实例已完成所有者首次认领，健康检查为 ready，独立 Codex CLI 登录完成。**网页连接保存、首个正式 Agent、项目任务和业务交付仍待验收**；早期测试实例的 Codex 两轮成功不代替主实例验收。

## 1. 启动与打开网页

本次主实例监听本机 3100，测试实例使用 3101。用户服务检查与启动：

```bash
rtk proxy systemctl --user is-active paperclip-main.service
rtk proxy systemctl --user start paperclip-main.service
```

Linux 本机可打开 `http://127.0.0.1:3100`。通过 SSH 使用网页时，在客户端建立仅监听客户端 loopback 的端口转发，再打开对应本机地址；不要因此把服务监听改成公网地址。

建议固定转发端口。例如在客户端运行：

```bash
rtk proxy ssh -N -L 127.0.0.1:3100:127.0.0.1:3100 your-user@your-linux-host
```

本次实际客户端曾使用不同端口。网址中的 `localhost`、`127.0.0.1` 和端口属于来源的一部分，不能随意替换后认为身份校验仍相同。

## 2. 创建账户时出现 Invalid origin

本次客户端打开的是 `http://localhost:56440`，与服务默认来源不同。确认真实页面地址后，在主实例私有环境中加入精确来源：

```dotenv
BETTER_AUTH_TRUSTED_ORIGINS=http://localhost:56440
```

这是本次值，其他安装要使用自己的浏览器实际来源，并保留原有必要配置。备份后重启主实例，按有限时间轮询就绪。不要使用任意来源通配来绕过检查。

本机验证使用合法请求结构和不存在的账户：允许来源返回 401 `INVALID_EMAIL_OR_PASSWORD`，随机来源返回 403 `INVALID_ORIGIN`。前者说明来源检查已通过，不代表测试账户登录成功；验证没有创建额外账户。

## 3. 为什么还要求登录 Codex

选择 OpenAI Subscription 时，Paperclip 需要为这条连接准备自己的 CLI 登录环境。现有普通终端中的 Codex 登录与网页新连接使用的 `CODEX_HOME` 不一定相同，因此已有订阅登录不保证新连接能读取它。

在运行 Paperclip 的 Linux 主机，执行页面提供的登录命令。以下仅展示隔离原则，实际目录使用页面显示的连接目录：

```bash
(export CODEX_HOME="$HOME/.local/share/agent-platform/paperclip-main/instances/default/ai-local-logins/CONNECTION_ID" && mkdir -p "$CODEX_HOME" && rtk proxy codex -c 'cli_auth_credentials_store="file"' login --device-auth)
```

浏览器完成设备授权后，再回 Paperclip 点击连接。设备验证码与凭据文件只在本机使用，不进入文档。

本次独立目录的 CLI 检查已返回 `Logged in using ChatGPT`。这证明授权完成，不能单独证明网页已保存连接或首次任务运行成功。

## 4. Claude 自定义 API 与其他执行方式

Paperclip 不只支持 Codex。选择相应本地适配器时，调用的是主机上的 CLI；Claude CLI 使用自定义 API 的方案需要继续向该适配器提供正确的环境、模型配置和凭据。

先核对所选适配器能找到 CLI，再使用与实际 Run 相同的环境完成小任务验证。普通终端里 Claude 可用，只能证明那个终端的配置可用，不能证明 Paperclip 进程继承了相同环境。本次保留现有私有模型配置，但 Claude 原生适配器尚未通过验收。

不要把 API key 写入公开配置、任务正文或 Wiki。选择 Codex 是本次已验证的执行路径，不代表每个 Agent 都必须登录 OpenAI。

## 5. 后续使用顺序与中文界面

1. 回网页确认模型连接保存成功。
2. 创建一个 Agent，选择已经验证的适配器和工作目录。
3. 创建项目和简单任务，先要求列出测试目录文件，不修改真实项目。
4. 检查 Run 状态、日志和实际输出，再逐步授权修改与 Git 交付。

以上是后续操作步骤，尚未全部执行。需要手动持续交互时，直接使用 Herdr / Collie；需要自动分配任务及查看运行记录时，使用 Paperclip 网页。

本次源码可见 `zh-CN` 翻译资源，但初始化语言仍为英文，未确认可用的界面切换入口。可以先用浏览器翻译和中文任务描述；不把存在翻译文件写成中文界面已配置完成。
